# 删掉会话，也删掉它留下的文件 —— dsh-plugin-session-file-purge

> 一个 DeepSeek Harness 插件。删除会话时，把这次会话**产生过的文件**列成清单，你勾选后先移入回收站、再删会话。
> 仓库根目录就是这个包，共 20 个文件、约 190 KB。

**本文是给人看的介绍**（可以整段贴到论坛或群里）。安装步骤、接口表、配置项、排障这类查阅型内容在 [README.md](README.md)；上传仓库的维护者备忘在 [发布到GitHub.md](发布到GitHub.md)。

## 一个很别扭的现状

Harness 类工具几乎都不记录「这次会话改过哪些文件」。会话日志里存的是会话自己的数据；模型通过 shell、python、构建脚本写出来的东西，运行时一概不知道。

所以「删除会话」这个动作天生是**半截的**：

- 会话日志删了，投影缓存删了，工作区记账删了 —— 侧边栏干净了；
- 但 `report.docx`、`charts/revenue.png`、`build/` 这一整坨还在你的工作目录里，而且**再也没有任何线索能告诉你哪些是这次会话产生的**。

越是用得久的用户越难受：攒了二十个会话、几百个生成文件，想清理只能靠回忆。

## 这个插件怎么解决

一句话：**会话开始时给工作目录拍一张快照，删除会话时把快照和现在做对比，差集就是这次会话的产出。**

```
会话开始 ──► 快照：{ 路径 → 大小, 修改时间 }   存到 ~/.dsh/session-file-purge/baselines/<会话id>.json
                │
                │   （会话进行中：模型写文件、跑脚本、你自己也在改）
                ▼
点击删除 ──► 对比快照 ──► 弹窗列出「新建 / 改动」两组文件，逐个可勾选
                │
                ▼
确认 ──► 选中文件按原相对路径移入回收站 ──► 然后才删除会话
```

### 为什么不用工具调用记录

会话日志里确实有 `write`/`edit`/`present` 的参数，理论上能把路径抠出来。但这条路有两个死结：

1. **漏报**。`python build.py` 一口气生成 20 个文件，日志里只有一个命令字符串；`npm run build`、输出重定向、任何脚本批处理都一样。真正需要清理的场景，恰恰是漏得最狠的场景。
2. **依赖内部格式**。会话日志是 zstd 压缩的私有格式，解析它等于把插件绑死在未公开的实现细节上，DSH 一升级就碎。

文件系统对比没有这两个问题：**谁写的、怎么写出来的都不重要，文件在会话开始后出现或变化就会被发现**，而它依赖的只是文件系统的 `stat`。代价是会话开始时多一次目录遍历（`node_modules`、`.git`、各类构建缓存默认跳过）。

## 用起来是什么样

```
┌─ 删除会话 ─────────────────────────────────────────────┐
│ 会话：季度汇报整理 (1)                                  │
│ 会话 ID：session-00000000-…                            │
│                                                        │
│ 本次会话产生或改动的文件                                │
│ 新建 · 3   [全选] [全不选]                              │
│  ☑ report.docx                          1.2 MB         │
│  ☑ charts/revenue.png                   240 KB         │
│  ☑ data/raw.csv                         18 KB          │
│ 改动 · 1   [全选] [全不选]                              │
│  ☐ src/config.yaml                      2 KB           │
│  合计：3 · 1.4 MB                                      │
│  [不清理文件，只删除会话]                                │
│                                                        │
│              [取消]  [移入回收站（保留会话）]  [移入回收站并删除会话] │
└────────────────────────────────────────────────────────┘
```

四个入口：

| 入口 | 行为 |
|---|---|
| 会话头部垃圾桶按钮 | 确认会话 → 文件清单 → 移入回收站并删会话 |
| 侧边栏会话行「⋯」→ 删除会话（含产生的文件）… | 同上，且不需要切换到该会话 |
| 侧边栏会话行「⋯」→ 清理本会话产生的文件… | 直接进清单，**只移文件、保留会话** |
| 侧边栏会话行「⋯」→ 打开文件回收站… | 逐批放回原处 / 永久删除 |

回收站里的东西随时能捞回来 —— 结束页就有「撤销：把文件放回去」。文件从不被静默删除：**唯一真正删除的接口只作用于回收站内的批次**。

## 几个刻意的设计选择

**默认只勾「新建」，不勾「改动」。** 改动类文件在会话开始前就存在，把整个文件移进回收站的风险比新建文件大得多，所以默认不勾、并在清单里明确写出这条风险。想要就自己勾。

**有预算、宁可漏报。** 单次对比最多访问 20 万个文件或超出时间预算就截断，并在弹窗里告诉你「列表可能不完整」。少列几个总比列错一个强。

**不碰依赖和版本库。** `node_modules`、`.git`、`.venv`、`__pycache__`、`.next` 这类目录从不进快照，也就不可能出现在待删清单里。

**路径全部双重校验。** 无论路径来自弹窗还是来自模型工具调用，都要过一遍 `resolveInside(root, path)`：解析后必须仍在会话工作目录内，`../`、绝对路径、同前缀的兄弟目录全部拒绝。

**长会话的清单会很长，所以有安全阀。** 会话活得越久，快照之后的「新建」越多（也包含你自己后来放进工作目录的东西）。默认只勾最新的 400 个，其余照样列出但不勾；弹窗最多渲染 2000 行。

## 安装

```sh
dsh plugin --profile <profile> add github:<用户名>/dsh-plugin-session-file-purge
# 或本地目录
dsh plugin --profile <profile> add file:/path/to/dsh-plugin-session-file-purge
```

装完**重启该 profile**（新增的 bundle 在组合阶段解析，运行中的实例不会热加载）。之后改插件源码刷新页面即可。

运行时零第三方依赖：宿主端只用 `node:fs`/`node:os`/`node:path`，客户端通过宿主提供的模块表拿 `react` 和 UI 原语。唯一的 peer `@deepseek-ai/dsh-tools` 是 optional —— 组合里没有工具注册表时插件照常加载，只是不注册 agent 工具。

## 附带的东西

插件还给模型加了一个工具 `session_files`，让 agent 自己也能查/清这次会话的产出：

```jsonc
{ "sessionId": "session-…", "mode": "list" }                 // 列出产生/改动的文件
{ "sessionId": "session-…", "mode": "purge", "paths": [...] } // 按路径移入回收站
```

以及一套 HTTP 接口（`/__sespurge/ping`、`/plan`、`/purge`、`/cleanup`、`/trash*`），其中 `/plan` 是只读的 —— 想接自己的界面或者写脚本都行。

**但这些接口不是"本机随便谁都能调"**。每个 handler 的第一件事是问宿主：`ctx.get('connection').admit(req)` —— 也就是 `/api` 自己走的那道闸。它先做 Host/Origin 栅栏（不是回环/监听地址/可信主机 → `403`，跨源或 `sec-fetch-site: cross-site` → `403`），再验浏览器会话（cookie 由进程启动 token 派生、HttpOnly、SameSite=Strict、绑定当前 hostname+端口、用浏览器伪造不出来的密钥签名；缺失或过期 → `401`），组合里没有这个服务就一律 `503`。POST 还要求 `content-type: application/json`（否则 `415`），跨站表单和 `<img>` 探针连"简单请求"都凑不出来。**没有这道闸，任何人只要碰到本机端口就能读会话标题、搬你的文件** —— 所以它是失败关闭的。

## 不是银弹：四条如实说明

- **基线只在会话开始时建立**。插件装上之前就已经开始的会话没有基线，弹窗会直接说「无法判断哪些文件是它产生的」，此时只能删会话。所以刚装好时，旧会话是清不了的 —— 这是设计使然，不是 bug。
- **你在会话进行中亲手改的文件也会进「改动」组**。快照看不出是谁改的。它不是默认勾选项，但请留意。
- **只覆盖工作目录内**。会话写到 `/tmp`、别的盘符或家目录别处的文件不在范围内。
- **会话删除链路复用了 DSH 的 `session_projcache` / `workspace` 存储结构**，大版本升级后需要跟着核对（当前对 `0.2.0-rc.2` 验证）。

## 工程上的一些事实（给要读代码的人）

```
src/index.js      1046 行   宿主端：快照调度、清单、回收站、会话删除链路、HTTP（含准入检查）、agent 工具
src/scan.js         254 行   目录遍历与基线对比（忽略规则、预算、越界校验）
src/trash.js        200 行   回收站：清单、移入、放回、永久删除
src/diagnostics.js   32 行   启动诊断日志
src/client.js     1055 行   客户端 bundle：头部按钮、两步弹窗、回收站面板、侧边栏注入
```

**158 条测试断言，五套，全部纯 `node`、零安装：**

```sh
node tools/run-tests.mjs
```

| 套件 | 断言 | 防的是什么 |
|---|---|---|
| `plugin-contract` | 16 | 插件契约：不导出 `Config`、导出形状、`optional` 声明 `connection`、`apply` 真的跑起来 |
| `bundle-install` | 29 | 安装契约：四处名字一致 + `engines.dsh` / `manifestVersion` / SemVer 声明 |
| `scan-rules` | 31 | 忽略规则、越界拦截、基线三类差异、预算截断 |
| `harness` | 52 | 宿主端行为：快照、清单、回收站、删除链路四步、入参校验、准入 401/403/503/415 |
| `client-smoke` | 30 | 客户端 bundle：三步渲染、勾选状态、请求体、回收站面板 |

其中两套值得单独说，因为它们在开发中各自抓到了真问题：

- **`bundle-install`**：启动器解析一个 bundle 要经过「bundles 条目 → node_modules 目录 → patch 文件 → 按行名 import」四步，**四处名字不一致时 bundle 会被静默跳过** —— 界面看起来是新的，但所有宿主端路由 404/405。这套测试在临时目录里复刻这四步并真的 import 一次。
- **`plugin-contract`**：cordis 的加载器会把插件导出的 `Config` 当成 schemastery 模式去校验。导出普通默认值对象会让配置解析抛错，`apply` 永远不被调用 —— 而我一开始就是这么写的，症状和上面那条一模一样。现在这套测试复刻了加载器这一步。

另外有个排查工具：`node tools/verify-live.mjs`，对运行中的实例走一遍只读路由，打印会话、基线、回收站状态，加 `--plan <sessionId>` 还能预先看一次「如果清理会移走什么」。它默认不带浏览器会话，所以会拿到 `401` 并直接告诉你「路由在、闸门在」——想真的看数据，把窗口用的 cookie 用 `--cookie "<name>=<value>"` 传进去。

## 和同类插件的关系

| | 会话数据（日志/缓存/记账） | 会话产生的文件 |
|---|---|---|
| `@pepsi-ai/dsh-plugin-session-delete` 等现有插件 | ✅ | ❌ |
| **本插件** | ✅ | ✅ 清单 + 回收站 + 撤销 |

两者界面形态一致（头部垃圾桶 + 侧边栏菜单 + 风险确认弹窗），**同时启用会出现两个垃圾桶按钮、两层弹窗**，二选一即可。选择本插件后，把另一个在自己的 profile patch 里 `disabled: true` 关掉。

## 验证状态与局限

- 开发与验证环境：Windows 11（PowerShell 7）+ Node 24.18.1 + DSH `0.2.0-rc.2`；在运行中的桌面客户端上完成了真机验证（ping / 会话列表 / 回收站 / 只读 plan 全部正常，已有 13 个会话建立了基线、3 批文件从回收站恢复或丢弃过）。
- 包清单声明兼容范围 `engines.dsh: ">=0.2.0-rc.2 <0.3.0"`、`dsh.manifestVersion: 1`；这两项当前不被安装器/loader 强制，属声明。
- **未在 macOS / Linux 上实测过**。路径处理用了 `path.sep` 归一化、越界校验用 `path.resolve` 前缀比较，理论上跨平台，但没有实机验证 —— 欢迎反馈。
- 客户端弹窗与菜单的文案是中文/英文双语（跟随界面语言）。
